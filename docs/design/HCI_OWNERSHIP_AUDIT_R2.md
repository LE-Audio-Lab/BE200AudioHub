# Round 2 — HCI Ownership Audit

Status: **Round 2 structural audit / handoff to Round 3**

Scope: L1-HCI Host, ACL, privacy/security/scan, and GATT. This note records
ownership observed in the actual implementation after the Round 2 source
migration. It does not redesign HCI behavior.

## 2. HciEngine state classification

The current `HciEngine` still composes multiple responsibilities. Round 2
does not split it, but classifies the fields so a later extraction does not
confuse durable state with transaction progress.

### A. Host-owned durable / authoritative runtime state

- `device: Device`
  - Bumble Host/Device state; single-owner mutable Host object.
- `link: QueueHostTransport`
  - Host-facing transport adapter and HCI observation journal.
- `connection_generations`
  - live raw ACL-handle -> generation fencing state.
- `next_connection_generation`
  - monotonic allocator for connection identity fencing.
- `acl_credit_audit`
  - controller ACL capacity/in-flight accounting.
- `iso_credit_audit`
  - controller ISO capacity/in-flight accounting; Round 3 ownership.
- `gatt_mtus`
  - current per-live-ACL negotiated ATT MTU facts.
- `gatt_poisoned`
  - per-ACL late-response safety fence retained until connection cleanup.
- `stream_routes`
  - session-fenced logical stream -> CIS route table; Round 3 ownership.

These are candidates for future explicit HCI Model components rather than
temporary operation objects.

### C. Output/deferred delivery buffers

- `gatt_reports`
  - typed report queue generated by GATT processing.
- `deferred_device_events`
  - temporary Bumble DeviceEvent delivery buffer.

These are execution plumbing, not authoritative domain state.

## 3. ConnectionToken / raw handle boundary

`ConnectionToken` currently contains public fields:

```text
connection_handle: u16
generation: u64
```

Observed production behavior:

- HCI owns generation allocation and raw-handle interpretation.
- Control stores/passes `ConnectionToken` as an opaque semantic identity.
- No production Control decision path inspected `.connection_handle` during
  the Round 2 audit.
- Review/HIL and tests intentionally inspect raw handles for evidence and
  diagnostics.

Risk:

> The public fields make a future ownership leak possible even though current
> production Control does not exploit it.

Do not solve this with a second wrapper or conversion type during structural
migration. Future interface hardening may make the token opaque outside HCI or
expose semantic accessors only.

## 4. Type-identity strangler discovered

While old and new ACL/GATT modules coexisted, Rust correctly treated e.g.

```text
hci_host::connection::ConnectionToken
plane::l1_hci::acl::connection::ConnectionToken
```

as distinct types even though their definitions were textually identical.

This exposed a real migration hazard in:

- `CisAclBinding`;
- HCI mailbox commands/reports;
- Control tests/helpers;
- Review/HIL helpers;
- GATT requests/reports.

Resolution:

- no `From` adapters;
- no compatibility re-export facade;
- all consumers were switched to the new owner;
- old ACL/GATT modules were deleted;
- test count returned from temporary duplicated 409 to baseline 362.

Rule for Round 3:

> Never keep two physical definitions of an HCI identity/API type alive during
> ISO/interface migration. Move ownership atomically or keep one owner and
> update paths.

## 5. Review / product boundary

The old `hci_host::smoke` module is an HIL orchestrator used by Review-2A, not
a product Host primitive.

It now lives at:

```text
review/support/hci_smoke.rs
```

Production HCI does not depend on Review support.

No Product -> Review reverse dependency was found during Round 2.

## 6. Hidden-global audit

The active HCI/ACL/GATT/remaining ISO source set was checked for module-level
mutable singleton patterns such as:

- `static mut`;
- `OnceLock` / `OnceCell`;
- `lazy_static`;
- `thread_local!`;
- module-level `Mutex` / `RwLock` state.

No such implicit mutable global state was found.

The Host state remains instance-owned through `HciEngine`, worker/stack
composition, transaction objects, and bounded mailbox state.

## 7. Single-owner invariant

Round 2 preserves the Bumble ownership invariant:

```text
HciHost worker
    owns HciEngine
        owns Device
        owns QueueHostTransport
        owns controller/connection transaction state
```

USB/Transport callbacks do not call Bumble directly. Transport remains below
HCI through `plane::l2_transport`.

## 8. Round 3 handoff

Round 3 should migrate, in bounded order:

1. CIG/CIS model and lifecycle;
2. ISO Host feature;
3. ISO path;
4. ISO credit;
5. ISO TX;
6. logical stream route;
7. HCI mailbox/interface.

The current Host files intentionally reference those modules through the
temporary `crate::hci_host::*` namespace. Those paths are the visible
strangler seam to remove in Round 3.

Round 3 must preserve:

- controller completions release capacity only;
- media time never advances from HCI completion;
- session-fenced logical route resolution;
- route bind/unbind ACK semantics;
- raw/logical ISO shared bounded lane;
- group-atomic ISO admission;
- route-first teardown/drain behavior.
